# P5 GEO SEO Static Generation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build deterministic static GEO/SEO pages and metadata from public Mayhem Oracle data without runtime LLM calls or private scoring leakage.

**Architecture:** Static pages stay in the Next.js App Router and derive content from `public/data` JSON plus curated translations. SEO helpers build bounded summaries and JSON-LD from public fields only, with route files rendering the helpers through `JsonLd`.

**Tech Stack:** Next.js App Router, next-intl, Vitest, TypeScript, public JSON catalogs, schema.org JSON-LD.

---

## Current Architecture

- `src/app/[locale]/augments/page.tsx` reads `public/data/augments.json`, normalizes augment sets, and renders a client-side index. Metadata already uses `localizedUrl()` and `languageAlternates()`.
- `src/app/[locale]/augments/[slug]/page.tsx` is SSG via `generateStaticParams()`, reads public augments, public champions, and sanitized public combo teasers, then renders an augment detail page. It is the safest first P5 target.
- `src/app/[locale]/champions/page.tsx` reads `public/data/champions.json` and renders a public index. Champion detail pages can read either public or member data through `loadChampionDetailData(source)`, so future SEO work must force the public source for indexable output.
- `src/app/[locale]/items/page.tsx` and `src/app/[locale]/items/[identifier]/page.tsx` read `public/data/items.json`, render item detail pages, and already have detail metadata.
- `src/app/[locale]/tier-list/page.tsx` redirects to `/champions`; future tier-list SEO should not add a thin duplicate route unless it has distinct static content.
- `src/app/[locale]/patch-notes` and `src/app/[locale]/patch-notes/[patch]` already have public-data-only metadata, JSON-LD, breadcrumbs, and live verifier coverage.
- `src/app/sitemap.ts` indexes static paths plus champion, augment, item, and patch detail routes from public data. First P5 slice does not need sitemap changes.
- `src/lib/__tests__/public-data-boundary.test.ts` is the main moat test. It already blocks internal telemetry, full combo pools, weights, pool rules, and internal fields from public catalogs.

## Public and Private Boundary

Allowed public SEO inputs:

- `public/data/augments.json`: slug, name, localized names, rarity, type, icon, sanitized `wikiDescription`, sanitized localized descriptions, public kit tags, lifecycle flags.
- `public/data/champions.json`: slug, name, localized names, public rank, public win rate, public pick rate, public tags/classes.
- `public/data/items.json`: item identity, public stats/descriptions, mayhem tags, public wiki notes.
- `public/data/combos.json`: capped S-tier teaser rows with only champion, augment, and tier.
- `public/data/meta.json` and `public/data/patch-notes.json`: patch identity and stable dates.

Forbidden SEO inputs:

- Any `data/internal` file.
- Private calibration exports, hidden model weights, prompts, full decision traces, raw pool internals, complete combo/trap sets, user/session/member data.
- Runtime LLM calls or request-time generated copy.

Forbidden public output keys and strings include `oracleScore`, `modelWeights`, `scoreBreakdown`, `computedPool`, `championPools`, `signals`, `provenance`, `data/internal`, and `prompt`.

## Sitemap Impact

- First slice: no sitemap change. `/augments/[slug]` detail routes are already generated by `generateStaticParams()` and included by `src/app/sitemap.ts`.
- Future slices may add route families only when each route is backed by public data, has deterministic static params, and has sitemap tests proving every advertised URL resolves.

## Proposed Page Types

1. Augment detail JSON-LD and breadcrumbs.
   - Public source: `public/data/augments.json`.
   - Output: `WebPage`, `BreadcrumbList`, `DefinedTerm`.
   - No private scores or full combo traces.

2. Item detail JSON-LD.
   - Public source: `public/data/items.json`.
   - Output: `WebPage`, `BreadcrumbList`, `Thing`.
   - Avoid raw scraper notes beyond already-public sanitized item fields.

3. Champion public overview summaries.
   - Public source: `public/data/champions.json` plus capped public combo teasers.
   - Output: bounded static summaries of rank/tier/classes and a few public S-tier augment links.
   - Do not expose member-only decision results or pool logic.

4. Patch-sensitive public summary blocks.
   - Public source: patch metadata and public lifecycle flags.
   - Output: “current patch” static copy and internal links.
   - Preserve existing patch-note live verifier green status.
